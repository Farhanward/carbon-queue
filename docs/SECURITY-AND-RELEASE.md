# CarbonFlow Security and Release Notes

## Device-bound licensing

The app computes a Windows-only device fingerprint from:

- Windows `MachineGuid`
- Windows username
- Computer name

The stored license is bound to this fingerprint. The development license key is:

```text
CF-DEMO-ALL
```

Production licensing should replace demo activation with signed `CF1.*` licenses generated by the developer backend. Do not put signing secrets inside the desktop app.

## Tamper resistance

The current build includes:

- Local SQLite database under the app data directory.
- Device-bound license activation.
- Tauri desktop shell rather than a plain browser site.
- Signed updater artifact generation.

No desktop app can be made impossible to reverse engineer. For commercial release, add:

- Code signing certificate for the Windows executable and installer.
- Server-side license activation and revocation.
- Signed license payload verification with a public key embedded in the app.
- Optional database encryption for sensitive customer data.

## Updates from the developer

Tauri updater support is configured in `src-tauri/tauri.conf.json`.

The updater public key is in the config. The private key is stored outside the repo:

```text
C:\Users\FARHAN\.carbonflow-signing\carbonflow-dev.key
```

For production, generate a new private key, keep it secret, update the public key in `tauri.conf.json`, and publish:

- The new installer/update artifact.
- The matching `.sig` file.
- A Tauri update manifest from your update endpoint.

## One-click Windows installer

Build the installer and updater signature:

```powershell
.\scripts\build-windows.ps1
```

The generated NSIS installer is written to:

```text
src-tauri\target\release\bundle\nsis\
```
